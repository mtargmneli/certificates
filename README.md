# TS — სერთიფიკატების გადამოწმების საიტი

ეს არის საბოლოო GitHub Pages ვერსია.

## რა აქვს ამ ვერსიას

- სერთიფიკატის ნომრით გადამოწმება
- QR ბმულიდან ავტომატური გადამოწმება
- მოქმედი / გაუქმებული / ვადაგასული სტატუსები
- მობილურისა და კომპიუტერის ადაპტური დიზაინი
- ქართული და ინგლისური სახელი
- კურსი, გაცემის თარიღი და გამცემი
- ცალკეული ჩანაწერები SHA-256 ჰეშით, საერთო ღია რეესტრის ფაილის გარეშე

## რატომ არის `records` ფაილები ჰეშით

სტატიკური GitHub Pages-ის შემთხვევაში მონაცემთა ნამდვილი დახურული ბაზა არ არსებობს.
ამ ვერსიაში ყველა მფლობელი ერთ `certificates.json` ფაილში არ არის ჩამოწერილი.
საიტი სერთიფიკატის ნომერს SHA-256-ით ჰეშავს და მხოლოდ შესაბამის ჩანაწერს ითხოვს.

ეს არ არის სრულფასოვანი სერვერული უსაფრთხოება, მაგრამ საჯარო სტატიკური საიტისთვის მნიშვნელოვნად უკეთესია,
ვიდრე ყველა სერთიფიკატის ერთ ფაილში გამოქვეყნება.

## ახალი სერთიფიკატის დამატება

### უმარტივესი გზა — Python სკრიპტი

კომპიუტერში პროექტის საქაღალდიდან გაუშვით:

```bash
python tools/add_certificate.py
```

შემდეგ შეიყვანეთ:
- სერთიფიკატის ნომერი
- სახელი/გვარი ქართულად
- სახელი/გვარი ინგლისურად
- გაცემის თარიღი

სკრიპტი ავტომატურად შექმნის სწორად დასახელებულ JSON ფაილს `records/` საქაღალდეში.

### ჩანაწერის მაგალითი

## GitHub Pages-ზე გაშვება

1. შექმენით GitHub repository.
2. ამ ZIP-ის შიგთავსი ატვირთეთ repository-ის root-ში.
3. გახსენით **Settings → Pages**.
4. **Build and deployment**: აირჩიეთ **Deploy from a branch**.
5. Branch: **main**, folder: **/(root)**.
6. დააჭირეთ **Save**.
7. GitHub მოგცემთ საიტის საჯარო მისამართს.

## მნიშვნელოვანი

`record-template.json`, `README.md` და `tools/` საიტის მუშაობისთვის აუცილებელი არაა.
შეგიძლიათ დატოვოთ repository-ში ადმინისტრირების გასამარტივებლად.

წარმოების რეესტრში განზრახ არ ჩამიმატებია გამოგონილი სერთიფიკატის ნომრები.
რეალური ჩანაწერები უნდა დაემატოს მხოლოდ ზუსტი, უკვე გაცემული ნომრებით.
